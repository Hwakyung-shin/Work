# 로그인 기반 온라인 동기화 연결

현재 코드에는 Supabase 연결 기능이 준비되어 있습니다. 실제 프로젝트와 공개 설정이 없으므로 아직 온라인 동기화가 활성화된 것은 아닙니다. GitHub Pages만으로 데이터를 저장할 수는 없습니다.

1. https://supabase.com 에서 본인 계정으로 프로젝트를 만듭니다. 프로젝트 데이터베이스 비밀번호와 비밀 키는 공유하지 마세요.
2. SQL Editor에서 이 폴더의 setup.sql 전체를 실행합니다. 사용자별 데이터 접근 제한(RLS)과 버전 충돌 방지를 설정합니다. 다른 사용자는 해당 계정의 데이터를 읽거나 쓸 수 없습니다.
3. 프로젝트 설정에서 Project URL과 **공개 Publishable key**(또는 legacy anon key)를 확인합니다. `service_role`, `sb_secret_` 키는 쓰지 않습니다.
4. 이 두 공개 값으로 sync-config.js의 url/key를 채워 사이트에 배포하면 모든 기기가 같은 저장소에 연결됩니다. 비밀 키는 파일이나 채팅으로 전달하지 마세요.
5. 앱의 동기화 설정에서 이메일로 회원가입합니다. 가입 확인 메일을 인증한 뒤 로그인합니다. Supabase Authentication의 Site URL을 https://hwakyung-shin.github.io/Work/ 로 설정하세요. 이메일 인증 후 앱에서 다시 로그인하면 됩니다.
6. **기존 데이터가 있는 Safari에서** 먼저 JSON 백업을 내려받고 로그인합니다. ‘이 브라우저 데이터를 온라인에 저장’을 선택하면 실제 업무가 업로드됩니다. 샘플 데이터가 있는 Chrome을 먼저 업로드하지 마세요.
7. Chrome/다른 기기에서 같은 계정으로 로그인하고 ‘온라인 데이터 불러오기’를 선택합니다. 이후에는 자동 저장하고, 입력 중이 아닐 때 약 15초마다 다른 기기의 변경을 확인합니다.

새로 로그인하거나 브라우저에만 남은 변경이 있으면 초기 데이터 선택을 표시합니다. 마지막 동기화 이후 로컬 변경이 없는 경우 다음 접속에서 온라인 데이터를 자동으로 불러옵니다. 동시 수정 충돌은 자동 병합하지 않으며, 양쪽 기록을 확인해 하나를 선택합니다. 선택 전 브라우저 사본을 별도 localStorage 키로 보관합니다(계정별 직전 사본). 네트워크 오류 시 로컬 저장을 유지하고 재시도합니다. 온라인에 저장되기 전 창을 닫을 경우 경고합니다. 무료 서비스의 용량·이메일 전송·휴면 제한은 공급자 정책에 따릅니다.

## 검증

UI와 데이터 전송·충돌·동시 수정·사용자별 접근 제한을 실제 Supabase 프로젝트에서도 검증한 뒤 사용해야 합니다. 로컬 mock 검증은 실제 서비스/RLS 검증을 대신하지 않습니다. 현재 사용자 프로젝트가 아직 없어 실제 두 브라우저 동기화는 미검증입니다.
